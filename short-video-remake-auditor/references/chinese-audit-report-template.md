# 中文审核报告模板

这个模板用于完整跑一次 `short-video-remake-auditor` 后，生成用户最先阅读的集成文件：`中文审核报告.md`。

审核不是泛泛评价视频好不好，而是判断成片是否保住了参考视频拆解出来的“神”、单元关系、压力场、视觉震撼、口播人味、声音节奏和产品主卖点。

## 硬性规则

1. 必须生成 `中文审核报告.md`，没有这个文件不算完整审核。
2. 正文、标题、表头、评分说明、问题描述、修复建议都使用中文。
3. 允许保留稳定编号、路径、文件名、TWE/TwelveLabs、原片原文、代码标识和 YAML 键名；除此之外，能中文化的都中文化。
4. 不能只给分。必须说清楚哪里不对、为什么不对、丢了什么用户心理、怎么改。
5. 音频和口播必须单独审核，不能只写“有背景音乐”或“口播正常”。
6. 每个主要问题必须落到成片时间段、参考要求、已见证据和具体修复动作。
7. 审核必须锚定导演技能已经批准的复刻方案，优先以 `中文最终交付.md` 和最新版 `14-visual-script*.md` 为基线。不能审核完另起一套脚本。
8. 修复建议只能给“回到既定脚本”的最小补丁：重剪、补拍、重配音、补贴片、补音效、改某一句。若既定导演方案本身错了，标为“导演基线缺陷”，建议退回 `short-video-remake-director`，不要在审核报告里直接重写全片。

## 文件结构

`中文审核报告.md` 使用以下结构。

```markdown
# 中文审核报告

## 一、审核结论

写总分、等级、是否可发布、最大问题。用三到六句话说清楚：成片是保住了神，还是只有形没有神。

必须包含：

- 总分。
- 等级判断。
- 最大扣分原因。
- 最优先修复方向。
- 本次证据是否完整，尤其是成片 TWE/TwelveLabs 是否跑过。
- 本次审核锚定的导演基线文件，例如 `中文最终交付.md`、`14-visual-script.v1.md`。

## 二、参考要求摘要

| 维度 | 导演基线要求 | 参考视频/脚本要求 | 成片应该触发的用户心理 |
|---|---|---|---|
| 神 | 写导演交付要求保留什么机制 | 写参考视频底层机制 | 写观众应该产生什么变化 |
| 视觉震撼 | 写导演脚本要求出现什么画面 | 写源片关键画面要求 | 写应该产生的感官冲击 |
| 文案方式 | 写导演脚本要求怎样替换口播 | 写源片说话方式 | 写应该像什么人说话 |
| 音频节奏 | 写导演脚本要求的 BGM、口播、音效 | 写源片背景音乐、口播、音效要求 | 写应该形成什么压力或信任 |
| 产品卖点 | 写导演脚本如何落主卖点 | 写目标产品主卖点 | 写主卖点如何落到画面 |

## 三、导演基线对齐

这一节判断成片有没有执行已经批准的复刻脚本，不生成新脚本。

| 基线镜头/台词/单元 | 既定要求 | 成片实际 | 偏差类型 | 最小修复 |
|---|---|---|---|---|
| 例如 G03 / P01.V02 / 顶部黄字 | 写 `中文最终交付.md` 或 `14-visual-script` 的原要求 | 写成片看到/听到什么 | 漏拍/重拍偏了/口播偏了/贴片漏了/节奏错了/导演基线缺陷 | 写回到原要求的动作，不另写一套新脚本 |

## 四、评分表

| 维度 | 满分 | 得分 | 主要证据 | 主要扣分 | 修复优先级 |
|---|---:|---:|---|---|---|
| 神和用户心理 | 15 |  |  |  |  |
| 压力场替换 | 12 |  |  |  |  |
| 单元关系 | 12 |  |  |  |  |
| 视觉震撼 | 15 |  |  |  |  |
| 结构节奏 | 12 |  |  |  |  |
| 音频、文案、字幕 | 10 |  |  |  |  |
| 产品主卖点 | 12 |  |  |  |  |
| 画面执行清晰度 | 7 |  |  |  |  |
| 合规和真实 | 5 |  |  |  |  |

## 五、主要问题和修复建议

| 问题编号 | 严重级别 | 成片时间段 | 导演基线要求 | 参考要求 | 成片实际情况 | 问题是什么 | 丢失的用户心理 | 修复类型 | 具体修复指令 |
|---|---|---|---|---|---|---|---|---|---|
| 问题一 | 一级/二级/三级 | 例如 0到3秒 | 写对应 `中文最终交付.md` 或 `14-visual-script` 要求 | 写对应源片单元或脚本要求 | 写看到/听到的证据 | 写清楚错或不足 | 写清观众心理没被触发 | 重剪/补拍/重配音/字幕贴片/音效/合规改写/导演基线缺陷 | 写回到既定脚本的最小修改 |

## 六、声音和口播审核

| 音频单元 | 参考要求 | 成片实际 | 问题 | 修复 |
|---|---|---|---|---|
| 说话人身份感 | 例如真人用户、权威主持、女主持收口 | 成片听起来像什么 | 是否人机、解释、过平、过急 | 重新配音或改句子 |
| 音色和情绪温度 | 源片冷、稳、急、热、压迫或亲近 | 成片听感 | 丢失什么 | 调整音色、速度、停顿 |
| 句子长度和节奏 | 源片短句/爆点/停顿 | 成片句子密度 | 是否说明书化 | 改成短句，绑定动作 |
| 背景音乐 | 源片音乐功能 | 成片音乐功能 | 是否没有压力/权威/节奏 | 换音乐或调混音 |
| 现场声和音效 | 开盖、水声、脆声、贴片声 | 成片是否存在 | 是否缺真实感 | 补现场声或音效 |
| 字幕节奏 | 黄字、白字、贴片是否卡点 | 成片字幕状态 | 是否平铺 | 重做字幕节奏 |

## 七、画面和单元状态审核

| 镜头 | 导演基线画面 | 成片画面 | 应有单元状态 | 缺失或错误单元 | 影响 | 修复 |
|---|---|---|---|---|---|---|
| 镜头一 | 写基线要求看见什么 | 写成片实际看见什么 | 人、产品、道具、场景、贴片、声音、心理 | 写漏了什么 | 写为什么影响复刻 | 写怎么补回基线 |

## 八、最终修复顺序

用列表给出三到八条优先级。先修会影响“神”的问题，再修画面清晰度，再修贴片、字幕、音效、合规。这里写的是修复路线，不是新版可视化脚本；除非标为“导演基线缺陷”，否则不要改变原导演脚本的镜头顺序和卖点顺序。

## 九、证据限制

说明哪些证据可靠，哪些不可靠。若成片 TWE/TwelveLabs 没跑或失败，必须写明这是部分审核，哪些维度置信度降低。
```

## 审核判断标准

- 如果成片画面像源片但用户心理没被触发，判定为“有形无神”。
- 如果文案事实正确但像说明书、课堂、产品页或 AI 总结，必须扣分。
- 如果主卖点没有落到目标产品的核心心智，必须扣分。
- 如果音频没有复刻源片的语气、速度、停顿、背景音乐压力，必须扣分。
- 如果画面无法从文字描述中重建，说明单元状态不清，必须扣分。
- 如果缺少关键贴片、字幕、角标、价格卡、免责声明等后期单元，按其对源片作用扣分。

## 最终自检清单

1. 文件是否存在：`中文审核报告.md`。
2. 是否先重建成片，而不是只看参考脚本。
3. 是否跑了成片 TWE/TwelveLabs；如果没跑，是否写明证据降级。
4. 是否给出总分、等级、最大问题和优先修复方向。
5. 是否单独审核声音、口播、背景音乐、音效和字幕节奏。
6. 是否逐条说清问题的时间段、参考要求、成片证据、丢失心理和修复动作。
7. 是否避免只写“冲击不够”“不像”“节奏差”这种没有证据和动作的评价。
8. 是否确认膳砂坊主卖点仍是健康养生和满罐水培菜结果，而不是工具教程。
9. 是否全中文表达，非必要英文是否已删除。
