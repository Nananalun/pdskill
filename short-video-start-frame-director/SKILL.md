# Short Video Start Frame Director

## Core Rule

This is a follow-on skill after a remake script exists. Do not redesign the video. Convert the approved visual script into one start frame per shot while preserving:

1. Source-video frame language: camera distance, blocking, posture, props, background, light, roughness, and sensory anchors.
2. Product truth: the product must match reference images, structure, material, usage state, and claim boundaries.
3. Shot purpose: each start frame must serve the shot's psychological beat and conversion role.

If product reference images are not available to the image model, do not pretend product fidelity is guaranteed. Either stop and ask for reference images, or explicitly mark the output as text-locked prompt packages only.

## Inputs

Expected inputs, accepting partial data with uncertainty:

- Visual script: the shot table or file generated by `short-video-remake-director`.
- Source video evidence directory: frames, opening frames, overview tile, metadata, and optional TWE segments.
- Product references: product photos, structure diagrams, usage process images, finished-result images, product visual locks, and product facts.
- Output target: prompt package only, generated start-frame images, or both.

For purple-clay sprouting jar work, product priority is health/养生 and process visibility. Result proof is secondary unless the user says otherwise.

## Workflow

1. Confirm the script and evidence
   - Read the visual script and identify shot rows, time ranges, scene purpose, actions, dialogue, sound, and overlays.
   - Read source evidence tiles and source frames. For the opening, inspect dense opening frames, not just overview frames.
   - If available, read the source unit graph to recover source IDs and sensory anchors.

2. Prepare the shot-frame workspace
   - Use `scripts/prepare_start_frame_workspace.py` when there is a Markdown visual script and a local evidence directory.
   - The script creates `shot_manifest.json`, per-shot folders, and nearest source-frame copies.
   - Treat its output as a starting point. Manually correct source frame selection when the nearest timestamp is not the best visual reference.

3. Map source frame to remake frame
   For each shot, define:
   - `source_frame_reference`: path and what to preserve from it.
   - `source_units_preserved`: camera, blocking, posture, prop layout, background, text rhythm, roughness, or lighting.
   - `product_units_inserted`: exact product, state, hands, sprouts, tray, water, labels, packaging, or usage card.
   - `units_deleted`: source product/category shells that must not carry over.
   - `overlay_plan`: subtitles, counters, stickers, labels, and prices as post-production unless they are physical props.

4. Split base image from overlay
   - Base start frames should normally avoid burned-in digital subtitles, counters, and stickers. Add these as an overlay plan.
   - Physical text that exists in the scene, such as a date sticker, usage card, price tag, or package label, can be inside the image if it is central to the proof.
   - If the source's identity depends on digital overlays, preserve their layout in `overlay_plan`, not by forcing the image model to render clean Chinese text.

5. Generate start-frame prompt packages
   For each shot, output:
   - start-frame goal
   - source frame reference
   - base image prompt in Chinese
   - English image prompt when useful for image models
   - negative prompt
   - overlay plan
   - product fidelity notes
   - acceptance criteria

6. Generate images when possible
   - If an image generation tool is available and can use the product references/source frame references, generate the frames.
   - If the tool cannot receive references, do not generate final product-sensitive frames by text alone unless the user explicitly accepts text-only visual locking.
   - After generation, inspect every image. Reject frames that drift from source framing, product shape/material, sprouts state, or shot purpose.

## Purple-Clay Sprouting Jar Start-Frame Rules

Use these rules when the product is the 紫砂水培罐:

- Product must look like a red-brown/purple-clay cylindrical sprouting jar, not a flowerpot, glass jar, plastic sprouter, or metal container.
- Important physical units: lid, jar body, upper pressure plate, perforated plate/篦子, water tray, clay texture, optional small label.
- Finished sprouts must be dense, upright, pale yellow-white, and naturally emerging from the jar. Do not show scattered, flat, wilted, noodle-like sprouts.
- Health/养生 frames should show process proof: beans, clean water, date sticker, daily rinsing, visible drainage, or family eating context.
- Do not generate medical, disease, guaranteed success, absolute safety, or fake certification imagery.

## Output Order

For full work, output files in this order:

1. `20-start-frame-source-map.v1.md`: shot-by-shot source frame and source unit mapping.
2. `21-start-frame-manifest.v1.json`: structured shot manifest for downstream generation.
3. `22-start-frame-prompts.v1.md`: per-shot Chinese/English prompts, negative prompts, and overlay plans.
4. `23-start-frame-qc.v1.md`: generated-image review or pre-generation risk checklist.

If images are actually generated, place them in a `start-frames/` folder with stable names such as `G01-start.png`, `G02-start.png`.

## Quality Gates

- Every generated frame must cite a source frame or explain why it intentionally diverges.
- Every product-sensitive frame must cite product references or state that it is text-locked only.
- Every shot must separate base image content from overlays.
- Do not add pretty props, clean studio lighting, or cinematic backgrounds if the source video's trust comes from rough street reality.
- The first-frame set must look like the same video after remapping, not like disconnected product posters.
